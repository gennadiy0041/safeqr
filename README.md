# SafeQR

Цифровая система контроля объектов безопасности предприятия.
QR-код на объекте (огнетушитель, аптечка, эвакуационный выход и т.д.) →
карточка объекта на телефоне → проверка / репорт о проблеме →
мгновенное появление у руководителя на dashboard.

Проект подготовлен как MVP для конкурса инновационных проектов
**AQMOLA POWER** (номинация «Информационные технологии» / «Энергетика»).

Стек: **Next.js 14 (App Router) + TypeScript + Tailwind CSS + Supabase
(PostgreSQL, Auth, RLS) + Vercel**.

---

## 1. Быстрый старт (15–20 минут)

### 1.1. Создайте проект Supabase

1. Зайдите на [supabase.com](https://supabase.com) → New project.
2. Дождитесь инициализации проекта.
3. В **Project Settings → API** скопируйте `Project URL` и `anon public` key.

### 1.2. Разверните схему базы данных

В Supabase Studio откройте **SQL Editor → New query** и по очереди
выполните три файла из папки `supabase/` (именно в этом порядке):

1. `supabase/schema.sql` — таблицы, типы, индексы
2. `supabase/policies.sql` — политики Row Level Security
3. `supabase/storage-policies.sql` — bucket `report-photos` для фото репортов
4. `supabase/seed.sql` — демо-данные (20 объектов для презентации)

### 1.3. Настройте переменные окружения

```bash
cp .env.example .env.local
```

Впишите в `.env.local` свои `NEXT_PUBLIC_SUPABASE_URL` и
`NEXT_PUBLIC_SUPABASE_ANON_KEY`.

### 1.4. Установите зависимости и запустите

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

### 1.5. Создайте учётную запись руководителя

В Supabase Studio → **Authentication → Users → Add user** создайте
пользователя (email + пароль) — это и есть логин для `/dashboard`
(`/login`). RLS-политики уже настроены так, что только авторизованные
пользователи видят и меняют статусы репортов.

### 1.6. Сгенерируйте QR-коды для демо-стенда

```bash
npm run generate:qr
```

Скрипт создаст `public/qr/*.svg` для каждого объекта из базы и
печатный лист `public/qr/print-sheet.html` — откройте его в браузере
и распечатайте (Ctrl+P) для демо-стенда.

## 2. Структура проекта

```
app/
  page.tsx                    — стартовая страница
  o/[code]/page.tsx           — карточка объекта (главный экран, открывается по QR)
  o/[code]/report/page.tsx    — форма «Сообщить о проблеме»
  o/[code]/check/page.tsx     — чек-лист «Проверить объект»
  login/page.tsx              — вход руководителя (Supabase Auth)
  dashboard/page.tsx          — панель руководителя (реестр, статистика, проблемы)
  dashboard/reports/[id]/     — карточка репорта: назначить, устранить, история
  actions.ts                  — все server actions (запись в БД)
components/                   — переиспользуемые UI-компоненты
lib/
  types.ts                    — типы данных (соответствуют схеме БД)
  instructions.ts             — инструкции по объектам (огнетушитель, аптечка…)
  supabase/                   — клиенты Supabase (браузер / сервер)
middleware.ts                 — защита /dashboard авторизацией
supabase/
  schema.sql                  — DDL: таблицы, типы, индексы
  policies.sql                — RLS-политики
  storage-policies.sql        — bucket и политики для фото репортов
  seed.sql                    — демо-данные для стенда
scripts/generate-qr.mjs       — генерация QR-кодов + печатного листа
```

## 3. Модель данных

- `organizations` — предприятия-клиенты
- `locations` — цеха/корпуса/этажи предприятия
- `safety_objects` — сам объект безопасности (огнетушитель, аптечка,
  эвакуационный выход, электрощит, аварийная кнопка, знак, оборудование);
  содержит уникальный `code`, по которому строится QR-ссылка `/o/<code>`
- `first_aid_items` — содержимое аптечки (позиция, количество, минимум)
- `reports` — зарегистрированные проблемы (категория, приоритет, статус,
  кто сообщил, кому назначено)
- `checks` — пройденные проверки (чек-лист + результат)
- `activity_logs` — единая история изменений по объекту

QR-код **не хранит информацию внутри себя** — только короткую ссылку
вида `https://ваш-домен/o/8F72K`. Все данные объекта подтягиваются из
базы в момент сканирования, поэтому обновлять QR-наклейку не нужно
никогда.

## 4. Демо-сценарий для жюри

1. Открыть телефон, отсканировать QR на «Огнетушителе №001» на стенде.
2. Показать карточку объекта → статус, инструкцию по применению.
3. Нажать «Сообщить о проблеме» → выбрать «Давление не соответствует
   норме» → отправить.
4. Переключиться на ноутбук, открыть `/dashboard` → показать, как
   проблема мгновенно появилась в разделе «Критические проблемы».
5. Показать «Аптечку №003»: списать пару бинтов кнопкой «−» → количество
   падает ниже минимума → автоматически создаётся репорт «Требуется
   пополнение» и статус объекта меняется на 🟠.
6. Показать «Эвакуационный выход №2» (в seed-данных уже 🔴 «заблокирован»)
   — пример критического кейса. Открыть «Сообщить о проблеме» и приложить
   фото прямо с камеры телефона — оно сразу загрузится в Supabase Storage
   и появится у руководителя на карточке репорта.
7. Вернуться на dashboard, нажать «Назначить» и «✅ Отметить
   устранённой» — показать полный цикл: **обнаружено → назначено →
   устранено → история**.

Итоговый месседж для жюри:

> QR → работник → проблема → база данных → руководитель → устранение →
> история. Это цифровая система управления безопасностью предприятия,
> а не просто QR-код с инструкцией.

## 5. Деплой на Vercel

1. Залейте проект в GitHub-репозиторий.
2. На [vercel.com](https://vercel.com) → New Project → импортируйте
   репозиторий.
3. В Environment Variables добавьте `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_BASE_URL` (укажите
   финальный домен Vercel).
4. Deploy. После первого деплоя переген­ерируйте QR
   (`npm run generate:qr` локально с обновлённым `NEXT_PUBLIC_BASE_URL`),
   чтобы наклейки указывали на прод-домен, а не на localhost.
